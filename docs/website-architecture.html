Publishable key · sb_publishable_…

Sits in the website's code, so anyone can copy it. It names the project and asks for public-level access. It proves nothing about who is asking; the sign-in token does that, and the rules decide.

Secret key · sb_secret_…

Skips row-level security. Lives only in .env, later also as a GitHub secret. Your scripts read it from .env; anyone holding it controls the game.

Database password

Connects straight to Postgres, past the API. The CLI uses it for supabase db push. Owner access: as powerful as the secret key, and more, since it can change tables.

Your CLI login

Not in .env. Tied to your Supabase account rather than this project; it lets the CLI list the keys and link the project.

6 · Boundaries

What never happens

Nothing writes to hockey_stats

Supabase and the website only ever receive copies. The master stays on your Mac, or in the seed file in git.

Nothing private in the JSON

Anyone can open /data/predictor/round-10.json. Picks, emails and accounts stay in Supabase behind the rules.

Features never point at each other

predictor may point at ref and public. A future blog or stats schema would too, never at predictor.

The secret key never leaves .env

Not in the website, not in git. The publishable key is the only one the public ever sees.
