# Pipeline: fixed bugs and integrity checks

Read before editing anything under `data/ingest/`, or after any re-ingest from the API.

Everything here is about the England importers. The German importer (`sources/hockeybundesliga.py`, `ingest import-bundesliga`) writes to its own database and has its own notes in [germany.md](germany.md). The `audit` command works on either database: point `DATABASE_URL` at `hockey_stats_de` to audit the German data.

1. **Source-label mismatch** — `eh_api_fixtures.py` originally tagged data `source="england_hockey_live"` instead of `"england_hockey"`. Since the DB's uniqueness check is `(source, source_id)` together, this silently duplicated every team/club/venue/competition that also existed in a historic season. Fixed by using the same source label in both importers. **If you ever add a third importer, it must use `source="england_hockey"` too.**
2. **Team/competition name whitespace** — the source API pads some names ("Fareham ", "Loughborough Students ", 6 competition names). Originally trimmed by hand in the DB, which every `import-fixtures` re-run silently undid — and a padded name breaks any *name*-keyed join (the predictor's CSV vs results dropped 2 of 60 matches, 2026-09-22). Now trimmed at the schema boundary (`schemas.Name`, every importer passes through it) and `maintenance.trim_names` runs first in `ingest repair` for rows already loaded.
3. **Player ID fragmentation** — 114 cases of the same real person (same name + same club) getting a new `player_id` across seasons; merged to one canonical row each, events re-pointed. ~43 cross-club same-name cases were left alone (likely genuinely different people). Now reproducible via `ingest dedupe-players` (also runs as part of `apply-aliases`).
4. **Club renames create a brand-new identity** — when a club renames/re-registers, England Hockey issues a *new* club and team `source_id` with no link to the old one (e.g. "Exe HC" 2022-23 → "Exeter HC" 2023-24: same side, finished 3rd in the same league both years). This breaks Elo/history continuity and is **invisible to name-based checks** (it's the inverse: same team, different name). Fix is `data/ingest/src/ingest/aliases.py` — old→canonical `source_id` maps, applied on every ingest by the loader (so re-ingesting an old season can't resurrect the stale identity) and to existing rows by `ingest apply-aliases`. **Only add an alias once someone who knows the league confirms it** — name similarity is not evidence (Chelmsford ≠ Cheltenham). To hunt for candidates: list teams that vanished after season N alongside teams that first appeared in N+1 and eyeball them. Aliases applied so far (2026-09-17):
   - **Exe HC / Exe 1 → Exeter HC / Exeter 1** (club + team alias).
   - **"Isca & University of Exeter 1" → "University of Exeter W1"** (team alias ONLY — Isca HC is a real, ongoing club with its own men's side, so no club alias). Online evidence: Isca's women joined the University of Exeter club in 2019 as a joint side; it was promoted to the Women's Prem for 2023-24 and relegated; the partnership then ended and the national-league place stayed with the university, which reappears as "University of Exeter W1" in exactly the relegation destination (Women's Division 1 South 2024-25). The merged team now has 91 matches across 5 seasons. Isca's women dropped to regional hockey (not in our data).
   - Not aliased: Brooklands-Poynton 1 (women's, merged into Brooklands HC) was already under the Brooklands club and simply got relegated out of the national leagues. A clustering pass over all 110 club names (town vs university pairs like Cardiff University ≠ Cardiff & Met, Nottingham Trent University 1/M1 = W/M pair of the same club) found no other renames.

5. **Events logged against an abandoned fixture instead of its replay** — when a match is abandoned and replayed, the club scorer may log the replay in the app against the *original* fixture, so the `status='A'` record carries the replay's goals and cards and the `status='R'` replay is missing some (seen once: Brooklands v Southgate, Sept/Oct 2025 — the replay had the 4 goals but the 7 cards sat on the abandoned record, invisible to every `status='R'` query). `maintenance.repair_abandoned_replays` moves them across when ≥ half the abandoned record's goals already match the replay's. Idempotent.
6. **Same player registered twice under a nickname** (Josh/Joshua Lang, Sam/Samuel, "Matilda (Tilly)"…) — the API issues a fresh player id per registration; `dedupe-players` only merges exact names. 11 such pairs found by scanning same-club same-surname pairs with the finals importer's nickname matcher; all aliased in `PLAYER_ALIASES` (2026-09-18). Re-run that scan (script in the session transcript; ~20 lines using `eh_altius._first_names_match`) after each new season's ingest.

7. **A postponement read as a 0-0 result** — the API sets `isResult: true` on a POSTPONED fixture (statusCode `P`, both scores sent as the literal string `"P"`, so `homeTeamScoreAsInt` is 0). `eh_api_fixtures._match_status` trusted `isResult` alone and would have written it as a played 0-0. Found 2026-09-23 by `ingest reconcile --season 2023/24`, where the historic importer's statusCode-based mapping disagreed with the live one. Fixed: `_match_status` now takes `statusCode` when it names a real outcome (A/P/W) and only falls back to `R`, and scores are stored only for `SCORED_STATUSES` (R/A/W). **First live case 2026-11-11:** Repton M1 v Leek 1 (7 Nov) came through as `P` with NULL scores, as intended, and the DB has no phantom 0-0 rows. The historic importer was always correct here.

8. **An event the source logged that isn't what it looks like** — e.g. a red card shown to a *coach*, not a player (East Grinstead W1, 19 Apr 2026: the person id is in no squad list, so counting it made the Women's Prem look like it had a player red card when it had none all 2025/26). `corrections.EVENT_REMOVALS` is the human-confirmed map of `match_events.source_id → why` to delete — the same bar as `SCORE_CORRECTIONS` (evidence recorded, specific enough to re-check the call); `maintenance.remove_known_bad_events` applies it in `ingest repair` so a re-import can't quietly restore the row. Confirmed by the user 2026-10-04; the coach's red card is the first and so far only entry.

**`ingest repair` runs every idempotent repair in one go** (trim names → aliases → score corrections → remove known-bad events → drop league-API finals → abandoned-replay events → name unnamed squad places from `SQUAD_IDENTITIES` → player dedupe). Run it after any re-ingest from the API, including `import-fixtures`.

## Checking the data

Three read-mostly commands, added 2026-09-23. Run `audit` after any ingest; run `reconcile` when you want to know the data still matches England Hockey.

- **`ingest audit`** — 22 integrity checks (four on squads added 2026-10-17) over what's loaded (goal events vs scoreline, events credited to a team not in the match, clock ranges, duplicate fixtures, shootout sanity, name hygiene, season structure, status codes), severity-ranked, writes nothing. Last report: `analysis/reports/data_audit_2026-09-23.txt`.
- **`ingest reconcile --season "2025/26"`** — re-walks that season's whole fixture list at the API and diffs it against the DB (missing, extra, score changes, status changes). ~900 calls and ~25 min per season, so don't run it casually. **All four API seasons reconciled clean on 2026-09-23**: 2022/23 (1,310 fixtures), 2023/24 (1,317), 2024/25 (1,311), 2025/26 (1,309) — zero missing, zero extra, **zero score differences**, and the single status difference turned out to be bug #7 in the checker, not the data.
- **`import-fixtures` only re-fetches played matches with *zero* events** (2026-10-19). A match where one club has logged and the other hasn't (Bowdon 2–7 Wimbledon, 17 Oct: Bowdon's 2 in, Wimbledon's 7 not) is never retried by it, so **run `backfill-events --season "2026/27"` after every `import-fixtures`**. That second pass recovered Wimbledon's and East Grinstead's scorers the same morning.
- **Late cards and re-attributed goals: fixed 2026-11-02 by `backfill-events --all`.** Plain `backfill-events` only retried matches whose goals didn't equal the score, so cards a club logged after we imported were never picked up (Cambridge City W1 v Birmingham 2s, 17 Oct: 4 cards missing; a "no cards all season" claim was nearly published on it). And because an event's `source_id` includes the player id, a goal re-attributed upstream was upserted beside the stale row (Bowdon 1-1 H&W, 1 Nov). Now `backfill-events` compares each match's event `source_id` set with the API's and, if they differ, **replaces that match's events wholesale**, then re-applies `EVENT_REMOVALS` in the same transaction. A replay with an abandoned twin is upserted only (repair may have moved events onto it, bug #5). First full run over 2026/27 (443 played, ~4 min): 17 matches rewritten, 93 stale rows replaced. The 7 Women's matches found short by hand (Surbiton v Wimbledon, Oxford Hawks v Cardiff & Met, Cambridge City v Birmingham 2s, Kirkby Stephen v Didsbury, Repton v Fylde, Repton v Alderley Edge, Wimbledon 2s v Spencer) all now match; **Men's had 2 short on cards** (Reading v Holcombe, 17 Oct: 1 stored, 5 upstream, Reading +4; Old Loughtonians v Southgate, 17 Oct: +1) and **7 matches had a re-attributed scorer** (same counts, different player). A re-run reports 442 of 443 matching (the other has no events upstream). `weekly.sh` now runs `--all --days 28` after the plain pass; run `--all` without `--days` now and then to sweep the whole season. Marlow 4-0 Havant (1 Nov) has 5 goal events upstream: the API's own disagreement, left as is.
- **`ingest backfill-events --season "2025/26" [--all] [--days N] [--dry-run]`** — re-fetches `/fixtures/{id}` for played matches whose goal events don't equal the scoreline (or every played match with `--all`, optionally only the last N days), because clubs log events days after we ingested. Rewrites only matches whose events differ from the API. Writes only matches the API actually has events for. Recovered 21 matches (5 in 2025/26, 16 in 2024/25 — 122 events, 507 player rows) on 2026-09-23. **2022/23 and 2023/24 are NOT recoverable** — sampled 10 and 6 matches respectively against the API, every one empty upstream, so don't burn 1,500 calls trying.

- **`ingest backfill-squads --season "2025/26" [--competition "Premier Division"]`** (2026-10-17) — fetches matchday squads for played league-API matches that have none in `match_players`. Writes squads only: events and officials are untouched (so it can't resurrect an `EVENT_REMOVALS` row) and players already in the DB aren't rewritten. Commits every 100 matches, resumes where it stopped, and waits `--pause` (default 1s) between calls. Squads start in 2023/24. **Any repair that merges players or teams must also re-point `match_players`** (`apply_aliases`, `dedupe_players` and `remove_league_api_finals` do); the audit's squad checks catch a miss.

Known residue after all of that (2026-09-23): 21 matches in 2024/25+2025/26 where the API's own event log disagrees with its own scoreline (99.2% of those two seasons reconcile exactly); one duplicate 2026/27 fixture (St Albans v University of Nottingham 2, 15 Nov, a midnight placeholder plus the real 14:00 row, both scheduled, both present in the API); and 21 events logged past minute 70 (up to 90 — post-match cards are plausible, a PC at 90 is scorer error). Cap minute filters at 70.
